How to structure a multi-tenant Laravel app for a fintech in Abidjan?

Asked 2 hours ago 1,204 views Solved
42

We're building a mobile money aggregator serving multiple merchants in Abidjan. Each merchant is a tenant and must never see another merchant's transactions. I'm torn between two approaches:

Single database with a tenant_id column and global scopes, or a separate database per tenant. Here's my current scope:

app/Models/Concerns/BelongsToTenant.php
trait BelongsToTenant
{
    protected static function bootBelongsToTenant()
    {
        static::addGlobalScope(new TenantScope);

        static::creating(function ($model) {
            $model->tenant_id ??= tenant()->id;
        });
    }
}

Is the global scope approach safe enough for financial data, or should I go fully isolated? What would you ship to production?

For fintech, I'd start with a single database + global scopes and only move to database-per-tenant once you hit real scaling or compliance limits. The scope approach is safe if you enforce it at three layers:

  1. A global scope on every tenant-owned model (you have this).
  2. Auto-fill tenant_id on create (you have this too).
  3. A middleware that resolves the tenant once per request and fails closed.
app/Http/Middleware/ResolveTenant.php
public function handle($request, Closure $next)
{
    $tenant = Tenant::where('domain', $request->getHost())
        ->firstOr(fn () => abort(404));

    app()->instance('tenant', $tenant);

    return $next($request);
}
The single biggest risk is a query that bypasses the scope — write a test that asserts every tenant model has the scope booted.

Counterpoint: if your merchants are banks or regulated PSPs, database-per-tenant can make audits and data residency far simpler. The stancl/tenancy package handles the switching cleanly and supports both models.

Pick based on your compliance requirements, not just engineering taste.
